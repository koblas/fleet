# fleet

Flux GitOps repo for the `nsc2108` k3s cluster. Flux syncs `clusters/nsc2108/` from `main`;
each file in `clusters/nsc2108/apps/` is a Flux Kustomization pointing at an `apps/<name>/`
directory (or, for exemplar, at the `exemplar-manifests` OCI artifact). Radar and Buildkite are
`HelmChart` objects run by k3s's built-in helm-controller.

## Workflow

All work here is the **Direct lane**: make the change, validate it, open a PR. No spec, no
scenarios, no pipeline, and no `.claude/pipeline.json`.

- Explain *why* in the manifest's comments, as the existing files do.
- Secrets are created by hand with `kubectl` and never committed; the comment next to the
  object that needs one says how to make it.
- `clusters/nsc2108/flux-system/gotk-*.yaml` is generated by `flux`. Regenerate it, don't edit it.
- Known debt goes to a GitHub issue labelled `debt` (what, why, and the trigger to pay it).
  Never a TODO list or TODO comment in a file.

## Validate

Build every directory that has a `kustomization.yaml` (CI runs the same loop):

```bash
find . -name kustomization.yaml -not -path './.claude/*' -exec dirname {} \; | xargs -n1 kubectl kustomize > /dev/null
```

`clusters/nsc2108` itself has none; Flux generates it. Nothing local checks exemplar's patches:
they apply to the remote OCI artifact, so a release that moves a patched path fails only in the
cluster (the JSON-patch `test` ops make that failure loud). Check with `flux get kustomizations`
after merge.
